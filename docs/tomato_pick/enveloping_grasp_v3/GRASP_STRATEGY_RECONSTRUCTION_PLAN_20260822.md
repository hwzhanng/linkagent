## 一、本轮重构总结（用户反馈驱动）

用户指出原策略"全指同步闭合"违背现实抓握逻辑——正确顺序应是**拇指先侧摆对置（与食/中指对齐），再进行抓握**，并要求参考历史存档权重（中小果径捏取，旧判据 89.65%），但专注于掌托大果。

### 已完成的重构（代码）

1. **`thumb_lead_fraction`**（`direct_joint_teacher.py`）
   - 拇指侧摆轴（channel 1 = thumb_joint0）在 coarse 阶段的 `thumb_lead_fraction` 比例处即完成对置 ramp，且**直达目标（open→target）而非 open→precontact**；拇指其余屈曲轴（channel 0/2/3）保持正常 precontact 节奏。
   - 依据存档控制器"幅度错峰"机制（thumb_opposition=1.0 vs global_flexion=0.267），非时间冻结。
2. **`fruit_speed_hold_m_s`**（`direct_joint_teacher.py`）
   - 果实平移速度超过阈值时**冻结闭指推进**（防止手指把逃逸的果实推得更远），但保留高力退让。
   - 修复审计 §5.4 明确点名的"教师丢弃果实速度"缺口。
3. **`digit_start_steps`**（上一轮已实现）
   - 逐指启动延迟支持（保留，供后续逐指承接实验）。
4. 全部参数接线：`evaluate_v3.py` / `train_v3.py` / `scenario.py` / 三基场景默认键；单测覆盖错峰与速度门控。

## 二、重构期间获得的证据结论

| 发现 | 结论 |
|---|---|
| 拇指侧摆轴 = channel 1（thumb_joint0），限位 [-1.0, 0.45] rad | thumb_lead 只能作用于 channel 1，不能作用于全部 4 个拇指通道 |
| 存档 `thumb_opposition=1.0` → thumb_joint0=+0.45（正），但当前 21-DOF 手正方向拇指力仅 0.1N（不接触） | **存档正方向值只适用于旧锁零形态，不能照搬** |
| 种子目标 thumb_joint0=-0.627（负方向）拇指力 0.6-3.1N | **负方向才是当前手的正确对置方向** |
| 轴序搜索：thumb_joint0=-0.062 指尖最近果面（接触）；CEM -0.608 为运动学对置 | 接触 vs 对置是不同优化目标，运动学对置动态未复现 |
| pose2 基线（种子目标+标准紧力带 detect=0.001+快时序@x0.035）= 3.33 指 | 紧力带擦碰锁存（同存档"首次包络即冻结"）是 3.33 主因；宽力带反降至 1-1.5 |
| 动态同帧 ≥3 指接触仍是硬墙 | V3-031/033 结论不变，opposition 门在其下游 |

## 三、当前锚定的最优基线

- 果位 `tomato_rest_xy = (0.035, 0.000)`（位姿扫描甜蜜区）
- 教师：种子目标（全指壳内几何，负方向侧摆）+ 标准紧力带（detect=0.001）+ 快时序（coarse=40/distal=30）+ attached_shape 诚实测量 + 顺序门
- 结果：meanMaxSim 3.33，过载 5/9
