## 节点 1：搜索器与几何审计不一致（发现）

### 现象

同一动作候选在 `link4_action_search.py` 中显示四指全部有测量接触，而 `thumb_geometry_audit.py` 显示直指离果实 4–8 cm。二者的结果不能直接比较。

### 根因

搜索器使用了 `proxy_only_collision`、`root-span=0.4`、`distal-filter-alpha=0.999`、代理/果实接触 offset 和逐指 assist；拇指审计没有复现这些参数，并且保留了未标定的供应商手部碰撞体。供应商 link4 碰撞盒很短，导致它们在审计中遮挡/干扰了 v2 指尖代理的物理解释。

### 修复

- `thumb_geometry_audit.py` 增加 `--proxy-only-collision`、proxy/果实 offset、`--root-span`、`--distal-filter-alpha`、平滑和逐指 assist 参数，并在 profile 应用前后统一覆盖。
- `train_v2.py` 增加 `--proxy-only-collision`，并将该字段写入 checkpoint `resolved_config`。
- `evaluate_v2.py` 增加同名开关并把解析后的值写入评估报告。

### 证据

- 原始不匹配审计：`artifacts/enveloping_grasp_v2/diagnostics/thumb_geometry_candidate210_matched_20260819.json`。
- 参数匹配、仅 v2 代理碰撞审计：`artifacts/enveloping_grasp_v2/diagnostics/thumb_geometry_candidate210_matched_proxyonly_20260819.json`。

## 节点 19：残差评估器物理代理一致性修复与逐步对齐（2026-08-19）

### 19.1 根因定位

- 逐 policy-step 对齐 `contact_closed_loop_probe.py` 与 `evaluate_v2.py`：两条路径的 14D 动作、目标动作、回合长度和 nominal 配置相同，但 evaluator 的指尖距离始终在代理接触壳外，导致四指没有真实碰撞。
- 根因不是残差控制器数学逻辑，而是 evaluator 命令同时使用了 `--proxy-only-collision` 与默认的非物理 proxy；这会关闭供应商碰撞体，却不创建可碰撞的 v2 指尖代理，形成“无指尖碰撞”的静默无效场景。旧闭环探针默认显式启用 physical proxy，因此出现假差异。

### 19.2 实现修复

- `evaluate_v2.py`：当启用 `--proxy-only-collision` 时自动启用 `fingertip_collision_proxy_physical`，并在 report 的 `resolved_contact_geometry.physical_fingertip_proxy` 中记录解析值；不改变硬件路径，仍保持 `hardware_command_allowed=false`。
- evaluator 新增 trace 诊断字段：选定 episode step 保存 action、measured link4/palm、tip distance、filtered distal、active joint 与 previous target；新增 `resolved_object_randomization` 和实际 gate/filter/command-rate 配置，避免只看终端成功率。
- evaluator 与 probe 均通过 py_compile；v2 测试保持 `10 passed`。

### 19.3 同一物理配置重放证据

产物：`artifacts/enveloping_grasp_v2/diagnostics/residual_base297_physical_proxy_fix_16_20260819.json`。

- v1_nominal_reliable、16 env、580 steps、37.5 mm 等径、6 mm physical proxy、proxy-only、0.3/0.1 mm fruit/proxy offset、40×35 mm cup、1 mm reset clearance、command rate 0.45 rad/s、virtual distal关闭、measured strict开启。
