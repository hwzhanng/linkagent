# 左手按 G20 协议运行官方 GUI

日期：2026-07-19

## 最终识别

当前替换左手必须在 SDK 中选择 G20。实机返回：

- CAN：can0，标准 ID 0x28，1 Mbps
- 嵌入式版本：1.0.10
- 序列号：LHT20-011-271-L-B-1-D
- 压感：第二代矩阵压感

虽然序列号和外观包含 T20/L20 标识，但动作协议与 G20 驱动一致。

## 协议修正

- 0x01：横滚位置
- 0x02：侧摆位置
- 0x03：第一指根位置
- 0x04：第二指根位置
- 0x05：第三指根位置
- 0x06：五指指尖位置，已经操作者目视确认
- 0x41～0x45：拇、食、中、无名、小指的六关节串联位置
- 0x49～0x4D：五指速度
- 0x51～0x55：五指扭矩
- 0x83：清除五指故障

旧 L20 网页程序将 0x05、0x06 当作速度和电流阈值是错误的；在本机 G20 协议中这两个帧会直接产生第三指根和指尖位置动作。旧入口已经禁用。

## 官方 GUI 启动

当前运行参数：

    driver: hand_type=left, hand_joint=G20, can=can0, is_touch=true
    GUI:    hand_type=left, hand_joint=G20, topic_hz=30, is_arc=false

启动前通过官方 G20 驱动将五指速度设置为 [80,80,80,80,80]。统一入口：

    scripts/start_left_g20_official_gui.sh

官方 GUI 启动后会立即周期发布页面当前姿态，因此启动入口本身属于可能产生动作的操作，必须先保持工作区净空。

GUI 的 20 维姿态由官方 G20 驱动转换为 0x41～0x45。11～14 是逻辑预留位；每指串联帧中仍存在未在 20 维 GUI 独立暴露的机构位置。

## 运行验证

ROS 节点：

    /linker_hand_sdk
    /hand_control_node

GUI 发布的话题为 /cb_left_hand_control_cmd。驱动已经返回完整 20 维逻辑状态：

    [255,4,4,1,3,253,144,144,135,113,211,0,0,0,0,254,0,0,5,0]

验证时 can0 为 ERROR-ACTIVE，发送和接收错误计数均为 0。
