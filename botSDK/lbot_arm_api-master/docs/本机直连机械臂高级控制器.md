# 本机直连机械臂高级控制器

## 1. 结论与边界

本机已在 `tools/local_arm_can` 的 CAN HAL 上补齐树莓派 `lbot_api_server` 的主要
高级控制能力，不依赖 MoveIt，也不依赖树莓派转发：

- 双臂 FK（正运动学）；
- 带种子、软限位和可达性判定的 IK（逆运动学）；
- `MoveJ` 关节空间梯形速度轨迹；
- `MoveJP`：目标位姿 IK 后执行关节轨迹；
- `MoveL`：笛卡尔直线 + 单轴姿态插值 + 连续 IK；
- `FollowP` 单点位姿跟随；
- 单独提供五次多项式平滑关节轨迹，供录制轨迹/VLA 使用；
- ROS 2 服务名和字段与树莓派 `/left`、`/right` 接口一致。

`MoveC` 没有伪造实现：树莓派当前版本的 `movec_function` 本身是 28 字节失败桩，
本机也明确返回 `success=false`。

本成果是根据已授权设备中可观察接口、未剥离符号、反汇编行为和实机计算结果做的
兼容重建，不是厂商源代码恢复。AArch64 闭源程序不能直接在 x86_64 笔记本加载，
因此 IK 使用 SciPy 带界最小二乘实现 TRAC-IK Distance 模式的外部语义。

## 2. 从树莓派确认的官方实现

当前树莓派文件与本地完整快照哈希一致：

- `lbot_api_server` SHA-256：
  `c476f23f76b0ec69fd14e03c66a655104011a4903e58271959c8774a6af3bbbb`
- `lbot_arm_driver` SHA-256：
  `06bcad9b591ab43ea1e79126c17a0e3a1288a68df60b89badb6586d68472dd8b`

反汇编和动态依赖确认：

- FK 使用 `KDL::ChainFkSolverPos_recursive`；
- IK 使用 `TRAC_IK::CartToJnt`，超时 `0.01 s`、容差 `1e-7`、`Distance` 模式；
- MoveL 使用 `KDL::Path_Line`、`RotationalInterpolation_SingleAxis`、
  `VelocityProfile_Trap` 和 `Trajectory_Segment`；
- MoveL 的旋转等效半径为 `0.01 m/rad`；
- 官方 MoveJ/MoveL 规划层以 `rclcpp::Rate(100)` 发布，即 `10 ms` 周期；本机
  保留 100 Hz 轨迹时间律，但直接 CAN 位置帧按已通过真机验收的 50 Hz 下发，
  且终点强制发送，避免经典关节在 100 Hz 连续写入期间出现反馈空窗；
- `speed <= 0` 或 `acce <= 0` 时，官方 MoveJ 使用默认值 `0.5`；
- FK 输出单位为米和 RPY 弧度，关节输入为弧度；
- FK 变换顺序为 `raw_fk * base_offset * flange_offset`，IK 按反序去除偏移；
- IK 请求不是恰好 7 个关节值时，官方使用当前关节作为种子。

本机 FK 已与在线树莓派验证：零位和全轴非平凡向量的最大误差约为 `2e-8`；树莓派
IK 返回的冗余臂另一组关节解，经本机 FK 计算后位置误差约 `4e-9 m`。7 自由度机械臂
同一位姿存在多组有效关节解，因此 IK 不要求与树莓派返回完全相同的关节数组，只要求
位姿、限位和连续性满足条件。

## 5. ROS 2 只读启动与计算验收

先确认 USB-CAN 接口。当前验收映射为左臂 `can0`、右臂 `can1`，但每次重新插拔后
仍必须以 CAN ID 核对，不能只相信接口序号。

```bash
source /opt/ros/jazzy/setup.bash
source tools/local_arm_can/ros_ws/install/setup.bash
export ROS_DOMAIN_ID=121
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST

# 示例：右臂只读，不能发 CAN
python3 tools/local_arm_can/ros_node.py --interface can1 --arm right
```

另一个终端可安全验证 FK：

```bash
source /opt/ros/jazzy/setup.bash
source tools/local_arm_can/ros_ws/install/setup.bash
export ROS_DOMAIN_ID=121
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
ros2 service call /right/fk lbot_arm_interfaces/srv/FK \
  "{joints: [0, 0, 0, 0, 0, 0, 0]}"
```

只读模式下 `movej/movejp/movel/followp` 会返回失败，不会暗中降级为运动。

## 6. 真机独占控制模式

真机运动前必须停止同一机械臂上的其他 ROS/CAN 命令发布者，确认接口、七关节反馈、
区域清空和急停复位。启动命令不会自动使能或运动：

```bash
# 右臂示例；只有现场安全确认后才允许使用该模式
python3 tools/local_arm_can/ros_node.py \
  --interface can1 --arm right \
  --allow-tx --poll-telemetry \
  --physical-confirmation RIGHT_ARM_AREA_CLEAR
```

随后还必须显式调用 `/right/enable_arm` 才可能运动。不要把启动参数中的确认词写入
常驻服务、系统服务或 VLA 配置；它只适合有人监护的单次验收会话。

运动链路的强制门禁包括：

1. 进程启动时显式允许 TX；
2. 七个关节反馈都在 `250 ms` 内；J1～J5 使用自动上报并由 50 Hz 主动查询
   兜底，J6～J7 使用 50 Hz 主动查询；
3. 同一运行时已显式使能；
4. 目标和每一个轨迹采样点均在软限位内；
5. 确认词与机械臂侧一致；
6. 同一机械臂一次只执行一条高级轨迹；
7. 相邻轨迹采样和直接 `/joint_cmd` 单步变化默认不超过 `0.08 rad`；
8. 调度落后超过 `50 ms` 时中止，禁止把积压帧瞬间补发；
9. 失能、急停或取消会阻止后续轨迹帧；ROS 使用可重入多线程执行器，阻塞式
   MoveJ 期间软件失能/急停回调仍可抢占后续帧。

## 7. VLA 接入建议

VLA 不需要 MoveIt 才能部署。树莓派官方高级控制器本身也没有 MoveIt 依赖。推荐按
动作空间选择接口：

- VLA 输出 7 关节目标：使用安全审核后的 `MoveJ`，或在上层用
  `sample_smooth_movej` 生成连续采样；
- VLA 输出末端位姿：先调用 IK 做可达性和限位检查，再使用 `MoveJP`；
- 明确需要末端直线：使用 `MoveL`，整条路径会逐点 IK，任一点失败即拒绝执行；
- 高频闭环策略：使用 `FollowP` 或 `/joint_cmd` 前，必须额外实现速度、单步变化、
  超时和控制权互锁，不能让模型输出直接裸发 CAN。

当前重建层复现的是官方控制器能力，不包含环境碰撞检测、自碰撞规划和视觉安全区。
如果 VLA 场景需要绕障或全身规划，再单独引入 MoveIt；不能把 IK 成功等同于路径安全。

## 8. 右臂高级控制器真机验收（2026-08-04）

验收对象仅为右机械臂；左/右末端灵巧手、手部 CAN 和相关进程均未操作。接口为
右臂 `can1`，1 Mbit/s；本机 ROS 域使用 `121` 并限制为本机发现，与树莓派域隔离。

验收过程：

1. 初始七关节最大偏离零位约 `7.5°`，以 MoveJ 缓慢回到
   `[0, 0, 0, 0, 0, 0, 0]`；最终零位误差小于约 `0.04°`。
2. 单关节从零位往返测试：J1、J3～J7 使用 `+20°`；J2 因当前官方软限位
   上界仅约 `+4°`，改用 `-20°`。七个关节均完成目标和回零。
3. J4 首次测试曾在约 `12.9°` 中止；增强诊断后确认是 J4 状态反馈年龄偶发
   超过 `250 ms`，CAN 控制器仍为 `ERROR-ACTIVE` 且错误计数为零。
4. J7 首次测试也因未运动的 J4 反馈达到 `259 ms` 被安全中止，证明原实现向
   七个关节以 100 Hz 连续写位置时，会影响某些经典关节的状态响应。
5. 修复方式是不放宽看门狗：J1～J5 保留 20 ms 自动上报，七关节增加 50 Hz
   主动查询；规划器仍保持官方 100 Hz 时间律，直接 CAN 位置帧限频为已验证的
   50 Hz，并强制发送精确终点。
6. 修复后 J7 `0→+20°→0` 最终复测通过，稳定峰值约 `20.10°`；原始帧监听
   测得 J1～J7 最大反馈间隔依次约为
   `[20.5, 20.7, 99.7, 119.9, 160.1, 60.2, 60.4] ms`，全部低于 250 ms。
7. 收尾时七关节回到零位，软件失能状态为 `22`；CAN `tx/rx` 错误、
   `bus-off`、`error-passive` 均为零。20 项自动测试通过。

验收后运行的是无现场确认词的遥测待机节点：可以发送状态查询，但使能和运动会被
确认词门禁拒绝。下一次真机运动必须重新确认区域清空和急停复位，并以单次验收命令
启动带 `--physical-confirmation` 的独占节点。

### 8.1 FK/IK 与末端空间服务真机验收

同日继续对除 MoveJ 外的全部高级接口进行验收：

| 能力 | 验收内容 | 结果 |
|---|---|---|
| FK | 零位与一组七关节非零姿态 | 零位结果与树莓派一致 |
| IK | FK→IK→FK 往返 | 位置误差约 `5.2 nm`，RPY 误差约 `1.2e-8 rad` |
| IK 安全 | 请求 `(5,5,5) m` 不可达位置 | 正确返回失败 |
